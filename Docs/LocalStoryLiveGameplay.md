# 실제 플레이 → 다음 회차 이야기

## 현재 연결 범위

Main에서 플레이하며 **NPC 대화가 끝나는 즉시 다음 회차용 생성 요청을 저장**하고 백그라운드로 작성합니다. 회차 전체 종료까지 생성을 미루지 않습니다. Excel의 자동생성이 켜진 NPC만 대상이며, 기존 기본 설정은 Guide/Gemma 켜짐, Duelist/Gambler 꺼짐입니다. 대화에서 실제로 읽은 기본 이야기와 후속 분기를 대상으로 합니다. 보지 않은 이야기·Variants는 임의로 생성하지 않습니다. 기록은 모든 NPC를 대상으로 합니다.

현재 회차의 지문은 교체하지 않습니다. 1회차는 작성한 원문으로 진행하며, 생성물은 회차별로 따로 저장해 다음 회차부터 읽습니다. 같은 회차에서 다시 만나는 이야기는 기존 해금/분기로만 결정합니다. 핵심 대사는 같은 사건 의미로 새로 표현하며 원문 문구로 잠그지 않습니다. 코인 변화·선택 ID·분기·핵심 속성은 원문에서 그대로 연결하고 LLM이 수정하지 못합니다.

대화 종료 체크포인트가 생성 시작 조건입니다. 대화를 열었다는 이유만으로 요청하지 않습니다. 사망/회차 종료로 활성 대화가 끝난 경우에도 실제로 표시된 이야기만 대상으로 삼습니다. 가상 테스트 기억이나 수동 테스트 적용을 실제 플레이로 취급하지 않습니다. 이미 실패한 과거 회차를 가짜로 다시 플레이하거나 자동 재생하지 않습니다.

현재 회차를 계속하는 입력은 다음 회차용 생성 때문에 막지 않습니다. 다음 회차를 시작할 때 그 회차에 들어올 요청이 아직 남아 있다면 Decision 진입에서 기다립니다. 실패한 최초 생성은 원문으로 진행하며, 이미 검증된 이전 생성물이 있다면 그 파일을 보존합니다. 내부 모델만 호출하며 외부 API/HTTP 서버는 사용하지 않습니다.

## 실제 플레이 기록과 꿈 같은 기억

두 가지는 별도로 저장합니다.

- `playEvents`/`playedCards`: 선택한 말·본 대사·결과·아이템·해금 등 실제 기록 전체입니다. Excel과 결과 Input의 감사 자료이며, 전부를 NPC의 기억으로 넘기지 않습니다.
- `dreamMemories`: 명시된 조건을 통과한 인상입니다. 모델에는 이쪽만 기억 자료로 전달합니다. "지난번 실제로 만났지", 정확한 옛 대사, 받은 아이템을 기억한다고 단정하지 않고 희미한 호감/불쾌감처럼 표현하도록 지시합니다. 형식 검사는 모델이 이 의미를 완벽히 지켰음을 보증하지는 않습니다.

조건 파일: `Assets/Decision_YYS/Resources/LocalStory/DreamMemoryRules.json`.
기본 조건은 관계 선택의 긍정/부정, 그리고 로키의 `loki_insult` 선택입니다. 중립·난독 연습·단순히 만난 기록은 기본적으로 전달하지 않습니다. 임의의 관계 점수 임계값은 추가하지 않았습니다.

태도 선택은 **1번 긍정 / 2번 중립 / 3번 부정 / 4번 혼돈**입니다. Initial의 로키 정체 반응 원문도 이 순서에 맞춰 정리했습니다. `choiceKind: Attitude`와 행동별 `choiceRole`을 명시하며, 게임은 번호를 추측하지 않고 작성된 역할을 기록합니다. 저장된 `choiceSlot`은 0부터 시작합니다. 선택 ID·분기·보상은 유지했습니다. 예를 들어 2번 장소 질문의 관계 보상 +1은 그대로지만, 태도는 중립이므로 기본 긍정 꿈 조건에는 포함하지 않습니다. 혼돈은 무조건 부정이 아니라 로키 모욕처럼 특정 선택 조건으로 기억합니다.

난독 체험·결투 시작 메뉴·동전 앞뒤·탐색 메뉴는 `choiceKind: Mechanic`으로 구분했습니다. 능력치 변형 JSON에도 같은 구분을 넣었으며 이 선택들의 문구와 기능 순서는 바꾸지 않습니다. 관계 선택의 역할/ID/배열 순서가 어긋나면 로더와 생성 입력 검사가 거절합니다. 과거 기록에 역할이 없으면 안정적인 선택 ID로 원문을 찾고, 찾지 못하면 Unknown으로 두며 예전 번호를 추측하지 않습니다. 기존 Edit은 수정하지 않고 새 설명 속성만 게임 적용 시 보완할 수 있습니다. 명시적으로 다른 역할이나 변경된 기능 연결은 허용하지 않습니다. 작성법은 [StoryChoiceAuthoring.md](StoryChoiceAuthoring.md)를 참고하세요.

규칙의 `enabled`는 켜짐/꺼짐, `characterId`는 NPC ID(`*`는 모든 NPC), `kind`/`choiceId`/`choiceRole`은 실제 저장 사건을 고르는 기준입니다. `requireRelationshipChoice`가 true이면 관계 대상 ID가 있는 선택만 인정합니다. `requiresUnlocks`는 해당 기록 회차에 모두 실제 획득돼야 하는 조건입니다. `runCompletedOnly`는 회차가 끝난 뒤에만 기억으로 확정할 조건이며, `impression`은 NPC가 느낄 꿈의 인상입니다. LLM이 해금 ID나 게임 보상을 만들지는 않습니다.

회차가 끝나면 완료 시점 조건을 다시 확인합니다. 통과한 인상이나 NPC 설정 등 생성 입력이 달라진 요청만 갱신하며, 같은 입력으로 전체를 반복 생성하지 않습니다. 생성 중 최신 요청이 들어와도 이전 작업이 최신 개정을 완료 처리하거나 덮어쓰지 못합니다.

## 요청 저장·중단·보존

`Saves/Runs/Run_0001/LocalStoryDialogueQueue.json`처럼 원본 기록 회차에 저장합니다. 이야기별 대상 회차·개정·상태·조건으로 선별된 인상·결과 경로가 포함됩니다. `LocalStoryRevisionRequest.json`은 기존 화면/Excel 호환용 상태 요약입니다.

- Pending/Generating: 생성 대기/중. Play 종료나 재컴파일로 중단되면 다음 실행에서 재개합니다.
- Ready: 다음 회차 파일 저장 완료.
- Failed: 원출력과 사유는 보존하며, 동일 입력을 무한 재시도하지 않습니다.
- Preserved: 수동 적용/수정 파일 또는 `Story.disabled.json`이 있어 보존한 경우입니다.

큐가 직접 만들었던 파일은 새 조건에 맞게 갱신할 수 있습니다. 하지만 파일을 직접 수정했거나 수동 테스트 적용본으로 바꿨으면 덮어쓰지 않습니다. 번호별 결과·Edit도 덮어쓰거나 삭제하지 않습니다. 원문 Resources 파일은 항상 유지합니다.

테스트 UI 생성에는 `테스트`와 게임 적용 아님을 표시합니다.
색은 Unity Editor Console용이며 플레이어 로그에는 태그 없는 일반 문장으로 남습니다.

## 해금 규칙의 의미

- 필요 ID는 `;` 또는 `,`로 여러 개를 구분하며 **모두 충족**해야 합니다. 빈 조건은 자동 해금하지 않습니다.
- 조건은 이전 및 현재 회차 Progress에 실제 저장된 unlockedIds 누적을 확인합니다. 기존 선택지 requiresUnlocks의 현재 회차 판정/보상 수치는 바꾸지 않았습니다.
- 새 조우 시작에만 판정합니다. 이미 읽는 중인 이야기나 저장 재개 지점을 다른 이야기로 갑자기 바꾸지 않습니다.
- 대상은 같은 NPC의 기존 원문 폴더 아래에 있는 Story 분기여야 합니다. 모르는 경로/다른 NPC/Variants 경로는 거절하고 기본 이야기를 유지합니다. 여러 규칙이 맞으면 위의 행부터 하나만 적용합니다.
- 숨은 과거도 빈 필요 ID로는 공개되지 않습니다. 새 해금 ID/새 분기는 게임에서 실제 부여할 기능과 원문을 준비해야 합니다. LLM이 새 아이템·조건·보상을 만들지 않습니다.

## Edit 참고와 결과 확인

기존 번호별 Edit은 삭제/수정하지 않았습니다. 실제 사람이 고친 것으로 검증되는 예시를 유지하되, 본 게임 프롬프트에는 말투 참고 3문장만 넣습니다. 완성 대화 전체를 답안처럼 제공하지 않습니다. 테스트 UI의 기존 참고 기능도 유지합니다. 학습/가중치 변경은 하지 않았습니다.

`Saves/LocalStoryTests/Index.html`에서 실제 대화 종료 생성 결과도 봅니다. 번호별 Results의 Input에는 전체 플레이 감사 기록과 선별된 꿈 인상, 해금·NPC 설정·프롬프트·참고 파일/SHA256이 분리되어 저장됩니다. Result는 실패 출력도 그대로 보존, Analysis의 saved/runtimeStage/runtimeError/verbatimReferenceLines로 적용 여부·선택 단계·실패·참고 문구 그대로 복사한 수를 확인합니다. 번호별 Edits는 기존처럼 화자·대사·분리된 options로 수정할 수 있습니다. Decision 테스트 UI의 저장 결과 읽기도 같은 기록을 사용합니다.

초안→교정 두 번 생성합니다. 교정을 시도한 경우 교정 검사까지 통과해야 게임에 적용하고, 실패하면 게임은 원문을 사용합니다. 원출력을 원문으로 덮어써 성공처럼 보여 주지 않습니다. 형식/화자 표기/수치/난독 검사는 의미·문학적 품질을 보증하지 않습니다. 문맥 이상은 실제 결과를 읽어 평가해야 하며, 별도 의미 평가/학습은 아직 하지 않았습니다.

2026-10-11 검사: Unity 컴파일 성공. 선택 순서/종류/ID 기억/기존 입력 호환 72개, 큐 56개, 회차 파이프라인 27개, 핵심/로더 18개, 흐름 35개, 원문/파서 334개, 장면 연결 34개, 로그 8개(총 584개) 통과. 별도로 실제 Edit 14번의 읽기 전용 적용 검사와 기존 말투 참고 기능도 통과했습니다. Edit·실제 세이브는 변경하지 않았으며 실제 모델 생성이나 플레이 완료를 대신 실행하지 않았습니다.

직접 확인: Main에서 NPC의 대화를 끝내고 Console을 `LocalStory`로 필터하세요. `N회차 → N+1회차용` 요청/생성 로그가 회차 전체 종료 전 나타나야 합니다. 현재 회차 지문은 그대로 유지됩니다. Index에서 선별된 꿈 인상·프롬프트·실제 결과를 확인한 뒤 다음 회차의 같은 NPC를 만나 비교하세요. 생성이 거절됐다면 빨간 로그와 Analysis의 사유를 확인하세요. 이전에 실패한 이미 끝난 회차는 이번 검사 때문에 자동 재생하지 않습니다.
