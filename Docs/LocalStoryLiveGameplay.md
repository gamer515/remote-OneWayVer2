# 실제 플레이와 다음 회차 이야기

[작성 구조](ChapterStoryAuthoring.md) · [테스트 절차](LocalStoryTestWorkflow.md) · [구현 구조](NarrativeImplementation.md)

현재 회차는 선택한 원문/생성본으로 진행한다. NPC 조우가 끝나면 실제로 읽은 기본 이야기와 후속 분기를 다음 회차 생성 큐에 넣는다. 보지 않은 이야기와 능력치 원문 변형을 임의로 플레이한 것으로 간주하지 않는다. 대화가 중단된 채 회차가 끝나면 실제 표시된 경로만 기록한다.

기본 자동 생성은 로키/Gemma다. 다른 NPC도 챕터 Excel의 자동생성 설정을 켜면 대상이 된다. 전체 대화 로그는 실제 기록으로 보존하고 모델에는 필터링한 기억과 필요한 문맥만 전달한다.

이번 회차의 실제 기억과 다른 회차의 Dream 인상은 별개다. 긍정·중립·부정·예상 밖 의도는 Explanation의 선택 ID별 설명에 지정한다. 버튼 순서로 의도를 추측하지 않으며 같은 의도를 여러 선택에 지정할 수 있다. 분류명은 실제 선택지에 붙이지 않는다. 단순 조작·난독 연습을 관계 태도로 추측하지 않는다. DreamMemoryRules는 유지했다.

로키의 표식은 긍정 반응 후 지급되며, 가방과 보드 위 아이템 모두 회차가 바뀌어도 유지한다. 다음 회차에 같은 선물을 주려 하면 이미 소유했다는 첫 선택지가 열리고, 선택하면 로키의 의아한 반응과 비밀 설명을 본다. 비밀까지 해금한 뒤에는 이미 용도를 안다는 선택지와 짧은 반응으로 달라진다. 현재 회차에서 직접 받은 선물은 실제 지급 기록을 상기한다. 반납은 실제로 소유를 제거하며 다음 회차에 복원하지 않는다.

대기·실패·유효하지 않은 생성본 때문에 플레이 입력을 막지 않는다. 새 대화를 시작할 때 검증된 생성본이 있으면 사용하고 없으면 원문으로 진행한다. 진행 중 대화는 재실행 시 고정된 지문·선택지를 복원한다. 원문 행동 연결 자체가 달라지면 다시 검사한다.

능력 배분은 첫 회차에 설명을 포함하고 2회차부터 같은 분기 파일의 Repeat 묶음으로 바로 시작한다. 다음 회차 생성 큐도 대상 회차의 Repeat를 사용한다. 첫 회차의 원문 설명과 아이템·비밀 대화는 유지한다. 현재 회차 내부의 새로운 LLM 재회 생성 연결, 관계에 따른 새 보상 규칙과 전투 약점 처리는 후속 단계다. 원본 메인과 선택지별 분기는 별도 파일이며 표식의 숨은 대화는 NPC의 Hidden 파일에서 관리한다.
