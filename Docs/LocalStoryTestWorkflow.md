## 화자·지문과 선택지를 구분하는 편집 형식

파일 이름의 앞 번호는 대응하는 Results 번호다. 예: Edits/0007__Gemma__Initial-guide__첫-만남.json.

```json
{
  "draft": [
    {
      "speaker": "로키",
      "text": "어이, 자네. 여기 있으면 안 돼."
    },
    {
      "speaker": "로키",
      "text": "나는 장난의 신 로키이지.",
      "options": [
        "네가 신이라고?",
        "왜 여기에 있는 거지?"
      ]
    }
  ]
}
```

교정본이 있으면 correction도 같은 모양으로 별도 보관한다. speaker에는 화자 이름만, text에는 지문만 쓴다. options는 그 지문에 대응하는 플레이어 선택지 문구를 한 줄씩 적는 별도 배열이다. 선택지가 없으면 options는 생략해도 된다. text에 로키: 같은 접두사나 사건 설명을 붙이지 않는다. 편집 파일에는 능력치/분기/상황을 다시 적을 필요가 없다.

기존 결과를 다듬을 때 지문의 순서와 개수, options의 순서와 개수를 유지하면 원본과 대응하기 쉽다. 선택지를 일반 플레이어 대화 줄로 섞지 않는다. 자유롭게 작성한 화자·지문도 말투/맞춤법/자연스러움의 참고 예시로 사용하지만, 자동으로 실행 가능한 Story JSON이나 게임 선택 분기가 되는 것은 아니다. 가중치 학습은 하지 않는다.

기존 상황 설명을 제거하기 전 파일 전체를 tmp/LocalStoryRecovery/EditSpeakerText-*.zip에 보관한다. 저장한 사용자 수정 대사와 선택지, Result/Input/Analysis는 바꾸지 않는다. 변환 뒤에는 편집기에 열린 옛 Results/번호/Edit.json을 닫고 Edits의 새 번호 파일을 열어야 한다. 옛 경로에 다시 저장하면 오래된 사본이 생길 수 있다.

## 2단계 큰 흐름 v7

현재 집필 기준은 v7.1이다. 첫 v7 시험(0005/0006)에서 정상 말로 풀린 난독과 화자/선택 의도 오류를 확인해, v7.1에는 고정 문구 강제가 아닌 발음 연출 참고와 직접 대사/서로 다른 선택 의도 구분을 명시했다. 기존 시험은 실패 사례도 그대로 보존한다.

- GuideIntroBrief.json은 실행 스토리가 아닌 집필 참고다. worldFacts는 세계관 사실, role=anchor는 핵심 사건, role=bridge는 연결 대화, reunionIntent는 재회 때 해당 자리의 목적이다. 원본 Story.json의 기능 실행 순서와 ID는 바꾸지 않는다.
- 재회는 같은 원문을 문장별로 바꾸지 않는다. 실제 기억으로 도입과 연결 대화를 새로 구성하며 이미 아는 정체를 처음처럼 소개하지 않는다. ‘이 세계에 이름을 남기고 싶나?’ 같은 질문은 가능하다. 새 능력/보상을 주겠다는 약속이나 기록되지 않은 과거 사건은 허용하지 않는다.
- 난독은 semanticText에 있는 숨은 의미와 선택 의도를 유지하며 발음 표현을 새로 만든다. semanticText 자체와 선택 결과는 모델이 바꾸지 않는다. 교정은 생성된 난독을 정상 한국어로 복원하거나 원문 난독으로 대체하지 않는다.
- GBNF는 출력 JSON의 카드 순서/개수/선택지 개수만 묶는다. 난독 text/options의 원문 강제, 문장별 특정 세계관 단어 강제, 재회의 첫째/둘째 문장 고정, 두 문장 강제, 중복 금지 지시를 제거했다. 고정 토큰/숫자와 최대 길이(대사 160자, 선택지 45자)는 유지한다.
- 자동 검사 통과는 의미 품질 승인과 다르다. 숨은 의미의 정상 문장을 그대로 출력한 난독은 간단히 차단하지만, 다른 표현이 정말 난독인지 또는 의미가 맞는지는 사람이 평가해야 한다. 세계관 표현을 동의어로 바꿀 수 있도록 정확한 단어 검사를 풀었으며 세계관 사실은 프롬프트에 전달한다. 별도의 완전한 의미 판정기가 생긴 것은 아니다.
- 새 실행은 상황 이름에 ‘큰 흐름 v7.1’을 표시하고 Input.json에 writingPolicy와 generationGrammar를 저장한다. 옛 결과는 당시 프롬프트/검사 그대로 보존한다. 새 검사로 옛 Analysis.json을 다시 쓰지 않는다.
- 테스트 UI/Index에는 실패·미완료 초안과 교정 원출력을 모두 표시한다. 네 파일 구조와 Edit.json의 줄바꿈 배열을 유지하며 기존 수정본은 덮어쓰지 않는다.

## 3단계 저장한 수정 문장을 테스트 생성에 참고시키기

Edits의 번호 파일을 수정하고 저장한 다음 새 테스트 생성을 누르면, 같은 이야기 경로의 편집 파일만 읽는다. 원출력과 같은 문장은 제외하고 실제로 바꾼 문장과 선택지만 참고한다. 다른 NPC나 다른 이야기의 수정은 섞지 않는다.

- 최근 결과부터 선택지 예시 최대 3묶음과 NPC 대사 최대 3개를 사용한다. 대사는 160자, 선택지는 45자 이내다. 파일 전체를 무제한으로 넣지는 않는다.
- 참고하는 것은 자연스러운 말투·맞춤법·직접 대답하는 선택지 형식이다. 예시의 사건·보상·과거 기억을 현재 이야기로 복사하라는 뜻이 아니다. 현재 원문의 사건 규칙과 실제 입력 기억이 우선이다.
- 생성 시작 시 예시를 한 번 읽어 초안과 교정에 똑같이 전달한다. 생성 중 편집 파일을 저장해도 이미 시작한 실행의 입력은 바뀌지 않는다. 다음 생성부터 반영된다.
- Input.json의 examplePrompt는 실제 전달한 예시, exampleSources는 편집 파일 경로·해시, exampleSummary는 사용한 수다. 실제 prompt/correctionPrompt에도 포함되므로 무엇을 참고했는지 확인할 수 있다.
- 수정 예시가 없으면 기존 입력 그대로 생성한다. 저장 중인 불완전한 JSON 파일은 건너뛰고 읽기 실패 수를 표시한다. 모델 원출력·편집 파일·게임 저장은 덮어쓰지 않는다.

이는 생성할 때 옆에 좋은 문장 예시를 놓는 방식이지 학습이 아니다. 가중치 변경, 파인튜닝, 본 게임 자동 적용은 하지 않았다. 예시를 연결했다고 자연스러움이나 의미가 자동으로 보장되는 것도 아니다. 큰 틀·중간 잡담 구조의 추가 변경은 현재 작업이 끝난 뒤 사용자 구상을 듣고 진행한다.

## 원문 핵심 속성과 명시적 게임 적용 — 2026-10-11

### 원문이 관리 기준

현재 Guide 도입의 원문 Story.json에 storyFrame과 선택적 coreMeaning을 작성했습니다.

- storyFrame.firstMeetingFlow / reunionFlow: 첫 만남과 실제 기억이 있는 재회의 전체 흐름.

### 실제 비교 0018~0022 — 해결된 부분과 남은 문제

UI의 공통 비교/권장 설정 전환은 없앴습니다. 모델 버튼으로 Qwen 또는 Gemma를 선택하며 설정과 시드는 고정합니다. 초안 뒤 교정이 순서대로 실행되고 두 모델을 동시에 실행하지 않습니다.

같은 Gemma/시드 12345/샘플링/원문을 사용했습니다. 첫 만남/모욕 재회는 시험용 가상 입력이며 실제 플레이어의 선택 기록을 추가하지 않았습니다. 수정 예시 없이 들어가는 입력은 v9의 3044자에서 2270자로 줄었습니다. 숫자 사건과 역할 접두사를 출력하지 않도록 입력을 분리했지만, 짧아진 입력만으로 자연스러움과 의미 정확성이 해결되지는 않았습니다.

0021 교정의 ‘이 광산은 길을 보여주는 곳이 아니야’와 지식 반환 뒤의 ‘돌려줄게’는 문법/상태 의미 문제가 남은 예입니다. 0022 Input에는 이전 ‘꺼져!’ 선택과 재회 태도 자료가 실제로 들어 있습니다. 기억 전달 누락이 아니라, 모델이 완성 예시를 복사하면서 이번 상황을 반영하지 못한 실패입니다.

완성 예시는 화자와 순서를 안정시켰지만 다양성과 재회 반응을 해결하지 못했습니다. 원문 대비 변화율은 Edit 복사를 새 생성으로 구분하지 못하므로 그 수치만으로 품질을 승인하지 않습니다. Analysis의 agentReview는 이 관찰이며 사용자의 humanReviews를 대체하지 않습니다.
원출력/입력/분석과 번호별 Edit은 모두 남겼습니다. 실제 게임 콘텐츠에는 적용하지 않았고, 다른 NPC/챕터로 확장하거나 학습/새 모델 설치를 하지 않았습니다. 다음 개선의 중심은 금지 지시를 더 늘리는 것이 아니라 수정 예시와 이번 만남 사이의 우선순위를 모델이 실제로 지키도록 만드는 것입니다.

최종 검사: 원문/파서 334개, 흐름 35개, 현재 장면 입력 34개, 간결 입력 21개, 완성 예시 15개, 핵심/격리 게임 로더 18개, Guide 설정 10개, 교정 11개 통과. 다른 NPC의 기존 부분 예시 검사도 통과했습니다. UI에서 모델 전환 및 설정 버튼 제거를 확인했고, Play 종료 후 추론 worker 0개와 runInBackground=false 복원을 확인했습니다.
작업 전후 SHA256 비교에서 원문·게임 저장·기존 테스트/수정본 JSON 150개가 모두 같았습니다. 신규 JSON 20개는 0018~0022의 Result/Input/Analysis와 별도 Edit입니다. Index와 사용법만 현재 상태로 갱신했습니다. 위 검사는 출력 문장의 품질 승인이 아닙니다.

### 실제 Gemma 시험 0017— 품질 승인 아님 

동일 Gemma/시드 12345/공통 샘플링/첫 만남/수정 예시 제외 조건으로 새 핵심 원문을 입력했습니다. 원문의 새 메타데이터가 추가돼 이전 시험과 원문 JSON 전체 바이트가 같다고 주장하지 않습니다.
초안 111.0초, 교정 70.5초, CUDA tinyBLAS 24층. 원출력은 Results/0017, 번호별 수정본은 Edits/0017__Gemma__Initial-guide__첫-만남.json에 보존했습니다.
내부 Guide → Player 표기와 숫자 코인은 출력되지 않았고 지식 차감/반환과 장난의 신 정체를 언급했습니다. 그러나 index 4에서 로키가 이해력을 잃은 것처럼 말하고 선택지는 정상 발화 참고를 복사했습니다. index 2의 광산/장난의 신 관련 문장, index 6의 설명체, index 8의 어색한 단어도 남았습니다.
교정은 index 4의 공백만 다듬고 핵심 오류를 해결하지 못했습니다. 초안·교정 모두 난독 선택지 정상복원 검사에서 거절됐으며 실패 출력도 그대로 보관했습니다. 프롬프트/핵심 속성으로 모델 품질이 보장됐다고 평가하지 않습니다.
실제 적용 UI에서 0017 AI 교정본의 저장 비활성과 실패 이유 표시를 확인했습니다. 기존 0014 Edit 교정본은 현재 원문 기능/핵심과 결합해 통과하며 미리보기를 확인했습니다. 해당 Edit을 고치거나 실제 게임 세이브에 적용하지는 않았습니다.
