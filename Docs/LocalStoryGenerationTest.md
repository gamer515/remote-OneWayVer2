# 내장형 LLM — 최소 이야기 생성 테스트

2026-10-11 추가: Main의 NPC 대화 종료 → 다음 회차용 백그라운드 생성, 조건으로 선별한 꿈 인상, NPC Excel 기록은 [실제 플레이 연결 안내](LocalStoryLiveGameplay.md)를 참고하세요. 아래 내용은 개별 Story 테스트의 범위입니다.

## 범위

Initial의 Guide/Duelist/Gambler와 그 분기/능력치 변형본 중 **한 Story씩** 생성하고 원문과 비교한다. 기존 씬/배치/애니메이션/원본 Story는 수정하지 않는다. 정상 Main 시작 경로에는 테스트 창이 나타나지 않는다. 챕터 전체 자동 생성, 미니게임 능력치 수식, Excel 관리, 파인튜닝은 후속 단계다.

## 실행

1. `Assets/Scenes/DecisionScene.unity`를 직접 열고 Play. Main을 거치지 않는 기존 Duel/도박 테스트 모드다.
2. 오른쪽 위 **이야기 LLM 테스트** 클릭. 실행 중 미니게임을 정리하고 보드 입력을 잠근다. 닫으면 원래 입력 상태로 복원한다.
3. 이전/다음 이야기로 원하는 경로를 고른다. 초기 대상 목록은 Initial Terrain의 `connectStoryCards`에서 실제 분기들을 따라 찾아 구성한다. Resources 폴더 전체를 임의 수정하지 않는다.
4. Guide 기본 이야기(`guide`, 변형본/분기 아님)를 고르면 **입력: 실제 기록** 버튼으로 실제 기록 → 첫 만남 → 우호 재회 → 모욕 재회를 순환한다. 세 가상 상황은 테스트용이며 화면에 표시된다. 이 선택을 플레이어 진행/관계/다음 회차 요청에 저장하지 않는다. **로컬 생성** 클릭. 모델 로딩과 추론을 백그라운드에서 수행한다. 소요 시간과 생성 중 출력을 볼 수 있고 취소할 수 있다. 5분 제한이 있다.
5. 왼쪽 원문과 오른쪽 **모델 출력 그대로**는 각각 스크롤 가능하다. 오른쪽은 모델이 반환한 JSON에 표시용 줄바꿈/들여쓰기만 추가한다. 대사 카드 사이에는 빈 줄, 대사 필드와 각 선택지에는 줄바꿈을 넣는다. 따옴표 안의 대사/선택지/escape와 모든 JSON 토큰은 변경하지 않는다. 실패·부분 출력에도 같은 표시를 사용하고, JSON이 아닌 출력은 그대로 표시한다. 테스트 기록의 `rawOutput`은 반환 문자열 그대로 보관한다. 게임용 후보를 재구성한 내용이나 원문으로 대체하지 않는다. 형식/선택지 수/고정 수치/일부 세계관 표현 검사는 별도 상태 표시일 뿐이다. 문자 유사도는 문자 편집 거리 기준이며 의미 일치도나 품질 점수가 아니다.
6. **의미/기억 사실 확인**은 사람이 직접 읽고 사실 관계를 검토했다는 테스트 기록(`reviewed`)만 남긴다. 자동 의미 판정이나 품질 점수가 아니며, 출력 변경/복구/게임 적용 기능도 없다.
7. 자연스러움 평가 버튼 두 개와 다음 회차 적용 버튼은 제거했다. 이 테스트 창에서 게임용 콘텐츠를 저장하거나 다음 회차에 적용할 수 없다.

원본 Resources Story는 테스트나 본 게임의 생성 과정에서 덮어쓰지 않는다. 테스트 생성/검토는 테스트 기록만 저장한다. 본 게임의 챕터 전체 자동 생성과 다음 회차 콘텐츠 확정 연결은 아직 후속 작업이다.

검사 실패/불만족 결과도 화면과 테스트 기록에 그대로 남긴다. 취소나 오류 발생 전까지 출력된 일부 내용도 남긴다. 모델이 아예 출력을 만들지 못했다면 출력 없음과 실패 사유를 표시한다. 원문과 같은 대사가 나오면 모델 자체가 그 대사를 재사용한 것이며, UI가 원문으로 복구한 것이 아니다. '원본 사용'은 실제 게임이 읽을 콘텐츠의 선택이지 테스트 결과를 삭제하거나 바꾼다는 뜻이 아니다.

## 실제 선택 기억

`Saves/Runs/Run_####/LocalStoryRevisionRequest.json` 중 최신 정상 요청을 읽는다. 파일을 읽기 위해 새 프로필을 만들거나 기존 진행도를 변경하지 않는다. 해당 화자와 같은 챕터의 실제 선택/관계/결과/아이템 사실 중 최근 중요 사건 8개를 입력한다. 기록이 없으면 이전 만남을 만들어내지 않는 첫 만남 표현 테스트다. 테스트 화면에 입력 회차와 사건 수를 표시하지만 게임의 회차를 변경하지 않는다.

현재 NPC 대사에 speakerId가 생략된 구형 카드도 guide/duelist/gambler 경로에서 인물 설정을 조회한다. 원본 메타데이터는 바꾸지 않는다.

## 2단계: Guide 대사 품질 시험

### 이번 변경: 초안과 한국어 교정본 비교

Guide 도입은 같은 내장 모델로 **초안 작성 → 한국어 교정** 두 번 실행한다. 다른 NPC/분기는 아직 한 번만 생성한다. 오른쪽 화면에 초안과 교정본을 각각 표시하며 둘 다 원시 출력으로 보관한다. 교정 결과가 실패하거나 더 나빠도 원문이나 초안으로 몰래 대체하지 않는다. 초안 JSON이 끊겼거나 카드 순서/선택지 수/고정 난독 표현이 틀리면 교정을 생략하고 사유를 표시한다.

파일 역할을 쉽게 설명하면 다음과 같다.

- `GuideIntroBrief.json`: 대사의 문구가 아닌, 그 장면에서 일어나야 하는 일과 선택지의 뜻을 적은 작성 메모다. 게임이 실행하는 이야기는 아니다. `sourceSha256`은 이 메모가 어떤 원본을 기준으로 만들어졌는지 확인하는 지문이다. 원본을 수정하면 메모도 검토해야 한다.
- `LocalStoryRewrite.cs`: 모델에게 주는 작성/교정 지시를 만들고 출력이 안전한 형태인지 검사한다. 초안은 일반 원문 문장을 보지 않고 의미 메모로 새로 쓴다. 교정은 그 초안과 의미 메모를 보고 맞춤법·띄어쓰기·어색한 문법을 다듬는다. 일부러 알아듣기 어렵게 쓴 카드에는 손대지 않는다.
- `LocalStoryNative.cs`: PC에 설치된 모델을 실행한다. 모델 자체를 학습하거나 인터넷에 대사를 보내는 코드가 아니다. 이번에는 다음 단어를 고르는 설정만 비교한다.
- `LocalStoryTestPanel.cs`: 비교 화면과 생성/취소 버튼을 담당한다. 검사 통과를 품질 합격으로 표시하거나 게임에 적용하지 않는다.

‘제약’은 카드 수·순서·선택지 수·일부 이름/숫자·난독 문구를 유지하는 규칙이다. JSON 문법 제약은 출력의 모양을 제한할 뿐 맞춤법이나 의미를 보장하지 않는다. 화자·기억·사건·선택 의도 보존은 모델에 지시하지만 사람이 읽어 확인해야 한다. 잘못된 결과도 평가할 수 있도록 그대로 보여준다.

실제 시험에서 카드 사이 공백만 계속 생성하는 실패도 확인해, [GBNF 문법](https://github.com/ggml-org/llama.cpp/blob/master/grammars/README.md)의 `ws`를 무한 반복이 아닌 한 글자 선택 공백으로 제한했다. 대사 내용을 바꾸는 규칙은 아니다. 가독성을 위한 줄바꿈은 화면에서 별도로 추가한다. 기존 실패 원시 출력은 삭제하지 않는다.

테스트 창의 **설정** 버튼으로 기존 설정과 Qwen 권장 설정을 바꾼다. 비교를 위해 시드는 `12345`로 고정했다. 같은 상황에서 두 설정을 각각 생성해 비교할 수 있으며, 같은 시드라도 설정/하드웨어/실행 환경에 따라 출력 차이는 있다.

| 설정 | 값 | 의미 |
| --- | --- | --- |
| 기존 초안 | temperature 0.65 / top_p 0.9 | 이전 코드 그대로. top_k/min_p는 기존 라이브러리 기본값 유지 |
| Qwen 권장 초안 | temperature 0.7 / top_p 0.8 / top_k 20 / min_p 0 | [모델 공식 권장값](https://huggingface.co/Qwen/Qwen3-4B-Instruct-2507#best-practices). 좋은 한국어를 보장하는 값은 아님 |
| 교정 시험 | temperature 0.25 / top_p 0.8 / top_k 20 / min_p 0 | 교정에서 표현을 덜 흔들도록 정한 시험값. 공식 권장 교정 설정이라는 뜻은 아님 |

temperature는 단어 선택의 흔들림, top_p/top_k는 다음 단어 후보의 범위를 조절한다. 모델의 지식을 바꾸거나 맞춤법 사전을 설치하는 설정은 아니다. 로컬 메모리 한계 때문에 context 4096과 출력 제한 1800은 유지한다. 현재 안전한 독립 실행 구조를 재사용해 두 단계마다 모델을 로딩/정리하므로 시간이 늘어난다. 각각의 시간은 로딩 시간을 포함한다. 품질이 확인된 뒤 모델을 재사용해 속도를 줄이는 작업을 따로 할 수 있다.

테스트 보고서의 `rawOutput`/`generated`는 항상 초안이다. `correctionRawOutput`/`corrected`는 교정 결과다. `draftSeconds`/`correctionSeconds`/`seconds`는 초안/교정/전체 시간이며 `draftParameters`/`correctionParameters`에 실제 설정을 기록한다. 파싱 실패 시 `generated` 또는 `corrected`가 없어도 원시 출력은 남긴다. 이 파일은 `LocalStoryTests`에만 저장하고 실제 회차 이야기 폴더에 쓰지 않는다.

Guide 기본 이야기만 `Resources/LocalStory/GuideIntroBrief.json`의 카드별 사건 의미/선택 의도를 입력한다. 일반 대사의 원문은 집필 프롬프트에 넣지 않으며, 난독 카드만 고정 출력으로 넣는다. 로키/왕국/광산/장난의 신 등의 정확한 표기는 별도로 전달한다. 다른 NPC·분기·능력치 변형본은 아직 이전 방식이다.

사건 요약은 게임에서 실행하는 Story가 아니다. 생성 모델이 게임 행동/ID/보상/코인 조작을 정하지 않는다. 원본 SHA256(줄바꿈 정규화 후), 카드 ID/순서/선택지 수를 대조하므로 원본을 편집했다면 요약도 검토하고 `sourceSha256`을 갱신해야 한다. 오류가 나면 입력 오류를 보여주며 오래된 요약으로 생성하지 않는다.

가상 우호 기록은 로키에게 광산에 있는 이유를 물었던 선택(관계 +1), 가상 모욕 기록은 `꺼져!` 선택(관계 -2)이다. 체력/민첩/지식/매력은 동일하게 5/5/5/5로 비교한다. 과거 사실은 첫 카드에서만 짧게 반응하도록 지시한다. 실제 기록 모드는 기존 요청을 읽기만 한다.

합격 기준은 사람이 읽었을 때 자연스러운 한국어, 화자/선택 의도 유지, 이전 선택에 맞는 반응, 사건/설정 유지다. JSON 검사 통과나 변경 카드 수만으로 품질 합격을 결정하지 않는다. 품질 승인 전에는 3단계(Initial 전체 확대)나 게임 적용으로 넘어가지 않는다.

이번 입력 개선은 학습이나 모델 교체가 아니다. `LocalStoryRewrite.BriefMessages`가 사건 요약과 과거 사실을 집필 지시로 만들고, `LocalStoryInference.Generate`에서 설치된 모델이 실제 문장을 생성한다. 테스트 화면은 반환 문자열의 내용은 유지하고 표시용 공백만 추가한다. 첫 카드의 재회 반응은 카드별 지시에도 명시했다. 모델이 지시를 항상 지킨다는 보장은 없으며, 검사 통과는 자연스러움/전체 의미 일치의 보증이 아니다.

## 저장

`Application.persistentDataPath/Saves/LocalStoryTests/`: 테스트별 원문/모델 원시 출력/입력 프롬프트/시드/시간/검사 결과/직접 검토 표시. 실제 선택 기록이 들어 있으므로 개인 데이터로 취급한다.

`Saves/GeneratedContent/For_Run_####/Encounters/<Story 경로>/Story.json`: 실제 게임에서 사용할 회차별 콘텐츠 저장 구조. 기존 EncounterContentRepository가 해당 회차에 읽고, 규칙이 달라졌거나 파일이 깨지면 원본을 사용한다. **테스트 UI는 이 폴더에 쓰지 않는다.** JsonUtility가 null을 빈 문자열/배열로 저장하는 차이도 정규화한다. 현재 자동 검사는 의미/자연스러움의 합격을 증명하지 않으므로 본 게임의 품질 기준/실패 복구 연결은 후속 작업이다.

## 모델과 배포

- 모델: [Qwen3-4B-Instruct-2507](https://huggingface.co/Qwen/Qwen3-4B-Instruct-2507), [bartowski Q4_K_M GGUF](https://huggingface.co/bartowski/Qwen_Qwen3-4B-Instruct-2507-GGUF), 고정 revision/크기/SHA256은 `Assets/StreamingAssets/LocalStory/ModelManifest.json`.
- 추론: [LlamaLib 2.0.5](https://github.com/undreamai/LlamaLib/releases/tag/v2.0.5)의 네이티브 C API를 직접 호출. 별도 프로세스/HTTP 서버/외부 API 없음. 최초 파일 설치만 인터넷을 사용한다.
- 현재 범위: Windows x64. GPU tinyBLAS 24층, context 4096, batch 256, CPU 6threads. RAM 약16GB / GTX1660SUPER 6GB에서 게임 VRAM 여유를 남기기 위한 시험 설정이다. GPU 초기화 실패 시 CPU AVX2로 대체하며 테스트 결과에 표시한다. 다른 기기/플랫폼/최종 게임 빌드는 아직 별도 검증 필요.
- 파일은 StreamingAssets에 포함되므로 Windows 빌드에도 들어간다. 모델 약2.50GB + 추론 DLL 약0.39GB(십진 단위). 모델과 DLL은 Git에 넣지 않고 복구 스크립트를 제공한다. 라이선스와 manifest는 추적한다.
- Play 종료/Editor 재컴파일 시 네이티브 추론을 취소하고 worker가 종료된 뒤 managed callback을 해제한다. 로딩 중 종료하면 모델 로딩 정리가 끝날 때까지 잠깐 기다릴 수 있다.
- 모델 출력 JSON 형식은 GBNF 문법으로 제약하며, 임의의 코드/분기/보상/ID를 모델 출력에서 실행하지 않는다. 문법 제약은 자연스러움이나 사실 의미 검증의 대체물이 아니다.

## 검사 명령

Play 중지 후:

```powershell
unity command set_autotick --enable true --format json
unity command recompile --format json
unity command recompile_status --format json
unity command run_script --file AgentScripts/LocalStoryEditorCheck.cs --entry LocalStoryEditorCheck.Regression --format json
unity command run_script --file AgentScripts/LocalStoryEditorCheck.cs --entry LocalStoryEditorCheck.Persistence --format json
unity command run_script --file AgentScripts/LocalStoryEditorCheck.cs --entry LocalStoryEditorCheck.Infer --timeout_ms 55000 --timeout 60 --format json
```

Regression은 형식/불변값/원본 보존, Persistence는 격리된 임시 저장소에서 다음 회차 적용/실패 시 원본 대체를 검사한다. ReportRegression은 UI와 검사 도구가 공유하는 초안 검증·집계를 검사하며, 재검사 집계 누적과 실패 출력의 원문 대체를 방지한다. Infer는 검사용 모욕 기억을 메모리에서 사용하며 실제 플레이어의 선택이나 세이브를 추가하지 않는다. 실제 플레이 기록으로의 대사 품질은 UI에서 별도로 확인한다.

`LocalStoryEditorCheck.OutputLineBreaks`는 대사/선택지 줄바꿈과 따옴표·쉼표·escape 보존, 부분 출력 토큰 보존을 검사한다. Play 중 `LocalStoryEditorCheck.RawOutputOnlyTest`는 격리 저장소에서 성공/실패 출력의 표시용 공백 추가, 원시 문자열 그대로 저장, 제거한 버튼의 부재, 직접 검토 표시 저장, 원본/게임 콘텐츠 미변경을 검사한다. 실제 이야기와 플레이어 세이브에는 적용하지 않는다.

2단계 입력 회귀 검사: `LocalStoryEditorCheck.BriefRegression`. Play 중 입력 버튼 검사: `LocalStoryEditorCheck.TestInputSwitch`. 세 상황을 같은 시드로 실제 생성: `LocalStoryEditorCheck.QualityCase --args '[1,12345]'`(첫 만남), `[2,12345]`(우호), `[3,12345]`(모욕). CLI 호출에는 `--timeout_ms 55000 --timeout 60`을 붙인다. 결과는 `LocalStoryTests`에만 보관한다.

두 단계 추가 검사: `LocalStoryEditorCheck.CorrectionRegression`. 실제 비교는 `StartTwoPass --args '[3,false]'`(모욕/기존) 또는 `'[3,true]'`(모욕/권장)에 `--timeout_ms 240000 --timeout 250`을 붙인다. 완료를 기다리는 비동기 명령이다. 시간 초과라면 작업이 계속될 수 있으므로 `TwoPassStatus`를 읽고 완료 전 새 비교를 시작하지 않는다. 이 시험도 테스트 보고서만 저장한다. Play 중 `ShowTwoPass`는 마지막 실제 시험 결과를 비교 화면에 띄우기만 한다.
