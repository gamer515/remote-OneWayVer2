# 내장 LLM 생성 검사

현재 절차는 [LocalStoryTestWorkflow.md](LocalStoryTestWorkflow.md), 원본 작성법은 [ChapterStoryAuthoring.md](ChapterStoryAuthoring.md)를 참조한다.

실제 모델은 Editor와 Windows x64 Mono 모두 Gemma 3 4B IT QAT Q4_0이다. 테스트 UI는 DecisionScene의 ‘이야기 LLM 테스트’에서 열고 본 게임 자동 생성은 실제 대화 종료 큐가 담당한다. 두 경로 모두 원문을 덮어쓰지 않는다.

전체 장면을 짧은 구간으로 나누어 모든 카드와 선택지를 생성한다. 생성에서 문구를 임의 제외하지 않는다. 형식·사건 순서·선택 연결·일부 상황 검사는 문학적 품질이나 모든 의미의 보존을 증명하지 않는다.

결과와 수정본은 회차/챕터/에피소드/NPC별로 모인다. Result에는 변경 대사, AI 원출력과 당시 원문, 마지막 실제 프롬프트·시간·모델·환경을 보관한다. Evidence.zip은 생성하지 않는다. 실제 플레이 전체 기록은 Runs에만 유지한다. 모델이 복사한 대사를 임의로 바뀐 것처럼 기록하지 않는다.

## 2026-10-25 구조 이관 검증

- 원본: 58 이야기 묶음, 103 카드, 52 선택지. 변환 전후 대사·행동·분기·설명을 런타임 데이터로 비교했다.
- 격리 저장/변경분/검토 보호/복구: NarrativeStoreCheck 80개.
- 전체 구간 생성·부분 교정·취소/재개: 50개.
- 실제 만남 종료 큐·Dream 분리·다음 회차 적용: 62개.
- 가방 밖 아이템 위치·소유·회수·중복 방지·실패 복구: 27개.
- 새 경로·Progress·수정본 저장 23개, 기존 자료 이관 13개, 원문 변경/자동 보관 한도 10개, 같은 NPC의 두 청크 분리 검사 통과.
- 실제 Gemma: 로키 9카드·8선택지 전체를 7개 구간으로 요청, 제외 0개, 재교정 0개, 약 74.76초. 문구가 달라진 카드는 5개다. 나머지도 생성 요청에 포함됐고 모델이 같은 문장을 출력했다.
- Windows 빌드 성공. Player에서 Gemma 단독 포함, 검증 캐시, 모델 세션 재사용, 표식 2구간 생성·로딩 검사 통과(약 40.15초).
- 실제 사용자 Saves 174개의 크기·수정 시각은 Player 검사 전후 같았다. 테스트 결과는 격리 경로에만 저장했다.

실제 생성 결과에는 반복 문장과 어색한 표현이 남아 있다. 프롬프트 문구·문맥 구성·샘플링과 품질/속도 개선은 다음 단계다. 이번 생성 시간은 한 대의 테스트 PC 결과이며 다른 PC의 성능을 보증하지 않는다. 진행은 생성 완료를 기다리지 않고 검증된 원문으로 이어갈 수 있다.
