# 고정된 이야기 품질 시험

## 이번 시험의 목적

현재 프롬프트를 더 고치지 않고 모델의 사건 이해력과 한국어 대화 품질을 판단한다. 형식 검사가 통과해도 의미가 틀리면 좋은 결과가 아니다. 다른 모델과 비교하기 전의 기준 결과다.

게임의 원본 JSON·실제 선택·실제 회차별 콘텐츠는 수정하지 않는다. 자동 교정이나 재생성 없이 첫 출력만 수집한다. 일부 대사가 틀려도 그대로 보관한다.

## 파일의 역할

- `Tests/LocalStoryBenchmark/Suite.json`: 사람이 확인할 기준과 시험 상황. 항목·배열을 줄바꿈하여 구분했다. **LLM에 추가로 전달하는 프롬프트가 아니다.**
- `AgentScripts/LocalStoryBenchmark.cs`: Editor에서 실행하는 독립 시험 도구. Assets 밖에 있으므로 게임에 포함되지 않고 씬 연결도 바꾸지 않는다.
- 기존 `LocalStoryRewrite.cs`: 현재 대화 지시·JSON 검사. 이번 작업에서 변경하지 않았다.
- 기존 `LocalStoryNative.cs`: 설치된 모델을 PC 내부에서 실행. 이번 작업에서 변경하지 않았다.

각 상황을 시드 12345·67890으로 한 번씩 생성한다. 합계 8개다. 시드는 단어 선택의 난수 시작값이며, 같은 시드라도 다른 모델이나 다른 실행 환경에서 같은 문장이 나오는 것은 아니다.

도입부는 현재 사건 요약 방식, 능력 배분은 현재 기존 원문 방식이다. 두 입력 방식의 결과를 섞어 하나의 프롬프트 성능으로 해석하지 않는다. Initial의 작은 표본이며 다른 챕터나 장기 이야기 품질을 보증하지 않는다.

## 고정하는 조건

원본, 현재 프롬프트, 난수 시드, JSON 문법, 샘플링 설정, 시험 규칙을 저장한다. SHA256은 내용이 바뀌었는지 확인하는 식별값이다. 실행 중 조건이 바뀌면 비교를 중단한다. 모델 파일도 기존 manifest의 크기·SHA256으로 확인한다.

현재 설정: 한 번의 초안 생성, context 4096, 출력 한도 1800, temperature 0.7, top_p 0.8, top_k 20, min_p 0. 모델 로딩·추론·정리를 포함한 시간을 기록한다. 모델을 바꿀 때 채팅 템플릿의 적용 차이는 별도 기록해야 한다. 모델이 제시하는 권장 설정까지 바꾸는 시험은 동일 조건 비교와 분리해야 한다.

자동 검사는 JSON·카드 순서·선택지 수·고정 표현·이름·숫자를 검사한다. 이 검사만으로 문장 전체의 의미·사실·한국어 자연스러움을 판정할 수 없다.

## 결과 확인

저장 위치:
`Application.persistentDataPath/Saves/LocalStoryTests/Comparisons/Runs/<모델-시험별 UTC ID>/`

매번 새 폴더를 만들며 이전 시험을 덮어쓰지 않는다.

- `Inputs.json`: 고정 입력과 검토 기준. 다음 모델의 비교에도 동일 입력을 사용해야 한다.
- `ModelManifest.json`, `Environment.json`: 모델, DLL 식별값, GPU·RAM 정보.
- `<상황>-<시드>.output.txt`: 모델 출력 그대로. 읽기 위한 줄바꿈만 추가한다.
- `<상황>-<시드>.report.json`: 원문·원시 출력·검사·시간. 원시 문자열은 변경하지 않는다.
- `<상황>-<시드>.review.json`: 의미·자연스러움·변화 정도의 검토 양식. 초기값은 미평가.
- `Summary.json`: 진행 상황과 기존 자동 검사 결과. 초기 도구의 `validStructure`도 순수 JSON 문법만이 아니라 고정 표현 검사를 포함한다.
- `Assessment.json`: 실행 후 별도로 만드는 JSON 파싱 여부와 자동 규칙 검사 구분 요약. 원시 출력·보고서·검토 파일은 수정하지 않는다.

과거 검사에서 메모리 조회가 0을 반환하는 환경은 측정 불가로 취급해야 한다. Unity 전체 프로세스 메모리는 모델만의 메모리와 다르고, GPU 메모리 총량은 실제 사용량이 아니다.

품질 평가에는 문제 카드 번호·실제 문장·틀린 이유를 적는다. 의미가 틀리면 실패다. 한국어와 표현 변화는 각각 1~5점으로 검토하되 품질 승인 전 게임에 적용하지 않는다. 테스트 결과에는 원문 대체를 하지 않는다.

## 실행

Unity 프로젝트가 열린 상태에서 공식 CLI를 사용한다. 현재 게임 UI에서 생성 중이면 종료될 때까지 기다린다. Play 종료 시 시험도 취소하고 이미 완료된 결과와 부분 출력을 남긴다.

```powershell
$unityCli = 'C:/Users/유영선/AppData/Local/Unity/bin/unity.exe'
& $unityCli command set_autotick --enable true --project-path C:/remote-OneWayVer2
& $unityCli command run_script --file AgentScripts/LocalStoryBenchmark.cs --entry LocalStoryBenchmark.Regression --project-path C:/remote-OneWayVer2
& $unityCli command run_script --file AgentScripts/LocalStoryBenchmark.cs --entry LocalStoryBenchmark.RunBaseline --timeout_ms 1100000 --timeout 1150 --project-path C:/remote-OneWayVer2
```

한 시험당 최대 240초다. 시간 제한에 걸리면 부분 출력을 저장하고 배치를 멈춘다. 무한 재시도하지 않는다. 긴 시험 중 에디터 명령 응답이 늦어지면 저장 폴더의 Summary로 진행을 확인할 수 있다.

Qwen 기준 시험은 기존 모델을 고정한다. 추가한 Gemma 비교 도구는 별도 파일 경로를 읽으며 게임 모델·프롬프트·원본 이야기를 교체하지 않는다. 모델 선택용 Inspector나 게임 적용 버튼도 추가하지 않았다.

## Gemma와 나란히 비교하기

- `Tests/LocalStoryBenchmark/GemmaManifest.json`: 공식 모델의 revision·크기·SHA256·출처·이용 조건을 구분해 보관한다. 체크섬이 다른 파일로 시험하지 않는다.
- `Tests/LocalStoryBenchmark/Compare.html`: 오프라인 비교 화면의 틀이다. 원문 / Qwen / Gemma를 카드별로 구분하고 선택지는 각각 한 줄씩 보인다. 외부 통신은 없으며 결과를 게임에 적용하지 않는다.
- `LocalStoryBenchmark.SmokeGemma`: 실제 모델이 현재 내부 엔진에서 로딩·GPU 실행·JSON 출력을 할 수 있는지 짧게 확인한다. 실패하면 전체 비교를 시작하지 않는다.
- `LocalStoryBenchmark.RunGemma`: 기존 Qwen의 `Inputs.json`을 그대로 사용한다. 8개 상황·시드와 문법·샘플링을 바꾸지 않고 한 번씩 생성한다. 새 폴더에 원시 결과를 보관한다.
- `LocalStoryBenchmark.BuildComparison`: 시험 결과를 읽어 Comparisons/Reports 아래에 `Comparison.html`을 만든다. 비교 데이터는 HTML 내부에 포함하며 같은 내용의 Comparison.json을 따로 만들지 않는다. 실제 결과가 없으면 ‘미실행’으로 표시한다. Qwen이나 원문으로 Gemma 칸을 대신 채우지 않는다.

Gemma 3는 별도 system 역할을 지원하지 않으므로 기존 system 내용, 줄바꿈 두 개, 기존 user 내용을 순서대로 합쳐 첫 user 입력으로 전달한다. 지시문의 글자는 바꾸지 않는다. 채팅 템플릿은 기존 엔진이 모델에 맞게 적용한다. [공식 입력 형식](https://ai.google.dev/gemma/docs/core/prompt-structure)

이는 모델뿐 아니라 양자화·모델별 대화 템플릿 차이를 포함하는 비교다. 현재 Qwen 샘플링 값을 동일하게 고정했으며 Gemma에 최적화한 설정이라고 주장하지 않는다. 메모리 실사용량은 아직 측정하지 않았다.

공식 조건 동의·다운로드는 사용자가 직접 한다. 테스트 도구는 계정·토큰·로그인을 처리하지 않으며 인터넷 추론도 하지 않는다. 다운로드한 GGUF를 Assets 안에 복사하지 않아도 된다.

### 이 PC에서 확인한 경로 주의 사항

`C:/Users/유영선/Downloads/gemma-3-4b-it-q4_0.gguf`는 공식 크기·SHA256과 일치했다. 다만 기존 네이티브 엔진은 이 한글 경로에서 문자 변환 오류를 냈다. Windows 짧은 경로에도 사용자 이름의 한글이 남았다.

테스트 전용 `C:/remote-OneWayVer2/Tests/LocalStoryBenchmark/Models/gemma-3-4b-it-q4_0.gguf`를 같은 파일의 NTFS 하드링크로 만들었다. 원본 다운로드는 이동·복사하지 않았고 모델 데이터 공간도 추가하지 않았다. 하드링크는 파일 내용을 공유하므로 어느 쪽에서도 내용을 수정하면 안 된다. 폴더별 용량을 단순 합산하면 같은 데이터가 두 번 보일 수 있다. 모델 경로를 읽는 용도로만 사용한다. 테스트 모델 폴더는 Git과 Unity 빌드에서 제외된다.

영문 경로에서는 기존 LlamaLib 2.0.5의 CUDA tinyBLAS 24층 로딩과 짧은 JSON 출력이 성공했다. 런타임 업그레이드·모델 가중치 변경은 하지 않았다. 이 호환성 검사는 이야기 품질 통과가 아니다.

### 실행 순서

조건 동의와 다운로드를 완료한 파일에만 `true`를 전달한다. 모델·기준 폴더를 따옴표 안의 실제 경로로 지정하며 비밀 토큰은 전달하지 않는다.

```powershell
& $unityCli command run_script --file AgentScripts/LocalStoryBenchmark.cs --entry LocalStoryBenchmark.ComparisonRegression --args '["<Qwen 기준 결과 폴더>"]' --project-path C:/remote-OneWayVer2
& $unityCli command run_script --file AgentScripts/LocalStoryBenchmark.cs --entry LocalStoryBenchmark.SmokeGemma --args '["<Gemma GGUF 경로>",true]' --timeout_ms 300000 --timeout 330 --project-path C:/remote-OneWayVer2
& $unityCli command run_script --file AgentScripts/LocalStoryBenchmark.cs --entry LocalStoryBenchmark.RunGemma --args '["<Qwen 기준 결과 폴더>","<Gemma GGUF 경로>",true]' --timeout_ms 2100000 --timeout 2140 --project-path C:/remote-OneWayVer2
```

기존 게임 추론과 같은 단일 실행 잠금을 공유한다. 테스트 생성 중에는 게임 UI의 이야기 생성을 시작하지 않는다. 모델 초기화 중 취소하면 초기화 정리가 끝날 때까지 잠시 기다릴 수 있다. 기존 Qwen 시험은 그대로 보관하며 새 시험으로 덮어쓰지 않는다.

- 우호 재회 12345, 카드 8 선택지: `자네가 정말 신인지 의심해봐`, `이 광산에 왜 있는 건지 물어봐`처럼 플레이어의 직접 질문이 아니라 지시문으로 썼다.
- 모욕 재회 12345, 카드 8 선택지: 장소를 묻는 원래 선택지가 `내가 이 광산에 있는 이유가 궁금한가?`로 바뀌어 질문의 주체가 뒤집혔다.
- 능력 배분 67890, 카드 4: 원문은 낮으면 느려지고 하나도 없을 때 못 걷는 두 조건이다. 생성 결과 `낮으면 움직이지 못해. 꼼짝도 못하겠지?`는 낮은 값 전체를 행동 불능으로 바꿨다.
- 능력 배분 12345, 카드 14: 기어 위는 추가·아래는 빼기라는 조작 설명을 `더 큰 것은 위로, 작은 것은 아래로`로 바꿔 실제 조작 의미를 잃었다.
- 능력 배분 12345에는 `앫겠지`, 67890에는 `blah blah`가 있어 한국어 품질 문제도 보인다.

능력 배분 17개 카드는 Gemma 두 시드에서 모두 표현이 달라졌지만, 변화량이 크다는 것 자체가 품질 개선은 아니다. 이번 조건에서는 더 빠르고 표기 제약을 잘 지켰다는 장점은 확인됐으나, 의미·한국어 품질이 안정적으로 개선됐다고 판단하지 않는다. 게임 교체는 하지 않았다. 사용자 만족도와 최종 선호는 아직 미평가다.

이전 개별 비교 HTML은 제거했다. 현재는 LocalStoryTests/Index.html에서 모델별 원문·생성문·입력·분석을 확인한다. 아래 수치는 당시 시험의 이력이며 새 시험이나 현재 품질의 보증이 아니다.

첫 Gemma 배치 보고서의 `sourceRun`·`targetRun` 필드에는 기본값이 남았다. 실제 시험 기억은 변경되지 않은 `Inputs.json`과 보고서의 `prompt`를 기준으로 확인해야 한다. 다음 실행부터 이 메타데이터도 입력 기억과 일치하도록 도구를 보완했다. 원시 출력·기존 보고서는 사후 수정하지 않았다.
