Gemma 3 4B IT QAT Q4_0, LlamaLib 2.0.5를 명세 기준으로 기록했다. 설치 모델의 실제 해시는 이번에 재검사하지 않았다. 정책은 예시 상한 2, 자동 교정 0회, 실패본 확인 허용, 과거 수정본 자동 예시 검색 비활성이다. 실패본 게임 확인 허용은 학습 자료 승인이나 품질 통과를 뜻하지 않는다.

이 두 장면과 관련 분기·기억 변형·말바꾸기는 이미 검토에 노출되었다. 최종 미학습 평가 자료로 사용할 수 없다. 학습 전에 다른 장면·상황 묶음을 선정해 별도로 고정해야 한다. 현재 최종 평가 장면은 미확정이며, 최종 평가 분리가 완료됐다고 보고하지 않는다.

## 3분 목표

사용자가 요청한 시간 목표는 한 장면 전체 결과를 180초 이내에 준비하는 것이다. 요청 수락부터 대기·검사·적재·모든 구간 생성·교정(발생 시)·최종 형식 검증·다음 회차 저장까지 측정한다. 차가운 시작과 모델 재사용은 따로 표시한다. 실패·중단·부분 결과는 시간 목표 달성으로 세지 않는다. 의미 품질 승인은 별도다.

발표 설정 보존에 따라 기존 런타임 제한 300초와 기존 비교 도구의 장면 제한 150초는 바꾸지 않았다. 180초는 평가 목표이며 현재 코드가 강제하는 중단 시간은 아니다. 검토에 사용한 과거 47.54초/20.80초는 격리 시험의 기록이며 현재 기준 재측정 또는 모든 기기의 통과를 뜻하지 않는다. 현재 GPU 조회는 GTX 1660 SUPER, 6144 MiB다. CPU/RAM은 조회 권한 제한으로 미확인이다.

## 정답 초안과 근거

근거는 로컬 `tmp/PromptComposition/bounded.json`, `bounded-mark.json`의 실제 Gemma 출력이다. 실제 플레이 로그가 아닌 격리 Synthetic 시험이다. 요청 메시지와 실패 문구를 검토 JSON에 보존했고 원본 보고서 해시를 기록했다.

| 검토 ID | 실패 내용 | 초안의 수정 방향 |
|---|---|---|
| knowledge-take | 지식 회수 대신 여행 목적 질문 | 로키가 여행자의 지식을 잠깐 빼앗는 장난임을 표현 |
| garbled-listener | 로키가 못 듣는 사람으로 바뀜 | 로키는 정상이며 여행자가 듣는 발음과 응답은 난독 유지 |
| knowledge-return | 반환 뒤에도 텅 빈 상태로 묘사 | 지식 반환 완료와 전후 차이에 대한 질문 |
| identity-choice | NPC/플레이어 관점 혼동, 모욕이 출입 요청으로 변경 | NPC 질문과 플레이어의 정체 질문·장소 질문·무관심·모욕 유지 |
| mark-no-invented-effect | 표식에 길 기억 기능 추가 | 표식 보관 요청만 표현 |
| mark-choice-intents | 앞 대사 반복, 의도 변경, 역할 접두사 | 용도 질문·반환·인물 질문·계속 진행 유지 |

과거 요청에는 과거 문맥과 잘못 생성된 앞 대사가 들어 있을 수 있다. 현재 Explanation과 의도 표현이 다른 부분도 있다. 따라서 역사적 요청과 이번 초안을 그대로 학습 쌍으로 확정하지 않는다. 사용자 검토 뒤 기존 프롬프트 조립 모듈로 현재 입력을 다시 만들고, 입력·정답의 일치와 앞 문맥을 재검토한 뒤 승인 자료를 별도로 구성한다. 기존 JSON이나 사람의 수정본을 자동으로 덮어쓰지 않는다.

조건 대비는 같은 장면 묶음 안에서 관리한다. 예를 들어 지식 회수 전/후/반환 후의 발화 상태, 실제 만남 기록과 꿈의 인상만 있는 경우를 구분한다. 꿈의 인상만 있으면 과거 만남이나 구체적 모욕 발언을 확정하지 않는다. 이 조건의 실제 실패 문구는 이번 여섯 사례에서 확인하지 못했으므로 실패 사례를 지어내지 않았다.

## 재사용 경계와 다음 단계

정답의 의미 기준은 기존 Explanation의 coreMeaning, semanticText, 선택 ID별 intent, participants, stateBefore/stateAfter, dialogueTiming이다. 초안을 승인받았더라도 이 기준과 다르면 정답 후보를 수정한다. 초안에 맞추어 Explanation을 변경하거나, 장면이 더 자연스러워 보인다는 이유로 의도·주체·상태를 재해석하지 않는다. 난독은 정의된 뜻과 질문/응답 의도를 유지하며 발음 표현만 변형한다. 의미 기준이 서로 충돌하거나 누락된 경우는 추측해 채우지 않고 검토 대상으로 남긴다.

프롬프트는 LocalStoryPrompt/LocalStoryPromptModules, 구간 생성은 LocalStorySections, 네이티브 추론은 LocalStoryNative의 LocalStoryInference, 검토 보관은 LocalStoryTestArchive/LocalStoryNotebook, 큐는 LocalStoryDialogueQueue, 게임 반영은 LocalStoryGameApply/EncounterContentRepository를 먼저 사용한다. NPC·사건·말투·선택 의도는 Characters/Explanation과 PromptModules에서 읽는다. 이번에는 모듈을 추가하거나 공통 제어 코드를 수정하지 않았다.

다음 필수 단계는 여섯 초안의 사용자 검토, 현재 입력 재구성, 장면 묶음 단위 자료 분리와 최종 미학습 평가 장면 확정이다. 그 뒤 정확한 원본 가중치·학습 도구·6GB 학습 가능성·변환 호환성을 시험한다. 승인 전 초안과 실패 출력은 자동 학습 대상에서 제외한다.

## 사용자 승인 이후 입력 대조 — 2026-10-29

사용자의 “그래 좋아”를 여섯 정답 초안의 승인으로 기록했다. 기준 고정 파일의 approvedCount=0은 고정 당시의 기록이며 현재 승인 상태는 AnswerReviewDrafts에서 관리한다. 승인과 학습 가능 여부는 구분하며 trainingEligible은 모두 false로 유지했다.

AgentScripts/ExportTrainingReview.cs를 Unity run_script로 실행했다. 이 도구는 기준 해시를 확인한 뒤 LocalStoryPrompt.Messages와 기존 Gemma 어댑터로 현재 입력을 재구성한다. 앞 문맥은 원문에 앞서 승인된 대사를 대입하며 실패 생성물은 사용하지 않는다. CurrentInputCandidates.json에 게임과 같은 user 메시지와 cards 출력 후보를 보관했다. 입력 재구성은 6건 모두 완료됐고 TryBuild, SameBindings, ValidateSituation, 길이 검사는 6/6 통과했다. 모델 추론과 개인 세이브 접근은 하지 않았다. 이 검사는 의미 승인이나 3분 성능 측정이 아니다.

의미 대조에서는 5건이 현재 입력과 일치했고 난독 응답 1건에서 수정 필요 사항을 발견했다. 두 번째 선택지의 intent는 “뜻을 알겠다는 반응”이지만 승인 초안 “이러언 마알인 거어야아?”는 다시 묻는 표현이다. 승인 원문은 보존하고, “으으응, 무슨 마알인지 아라게써어!”를 수정 후보로 기록했다. 이 수정 후보는 사용자 미승인이므로 자동 반영하거나 학습에 내보내지 않는다. 형식 검사가 의미 오류를 잡지 못하는 구체적 사례다.

현재 후보 6건은 모두 같은 NPC 만남 계열이므로 무작위로 train/validation/test에 나누지 않는다. 장면 이름이 달라도 해당 분기·기억 변형·말바꾸기는 같은 누수 그룹으로 묶는다. 기존 장면 카탈로그는 후보 파일에 재사용 가능한 경로 목록으로만 기록했으며 다른 NPC의 정답이나 미학습 평가 통과를 만들지 않았다. 다음은 위 선택지 수정 검토와 별도 장면 묶음의 검증/평가 자료 확정이다.

## 현재 진행 상태 — Explanation 보존 지시 반영

사용자는 Explanation에 정의된 의미를 유지하며 진행하도록 재확인했다. 난독 응답에 대해 별도 새 표현의 승인을 요구하며 작업을 멈춘 처리는 해제했다. 의미가 어긋난 두 번째 응답을 Explanation의 loki_garbled_guess.heardText인 “으응, 아라써어!”로 교체했다. 새 문장을 발명하지 않고 기존 자료를 그대로 재사용한 것이다. 기존 초안과 변경 근거는 검토 JSON에 보존했다.

현재 입력 6건을 다시 조립했고 형식·길이·상황·연결 검사는 6/6 통과했다. TrainingPairs.jsonl에는 현재 게임의 user 메시지와 JSON cards 정답을 assistant 메시지로 짝지은 6건만 포함한다. 원시 실패 출력이나 미승인 생성 수정안은 포함하지 않는다. 앞 문맥은 원문 및 의미가 정렬된 정답을 사용한다.

DatasetSplitPlan.json에 Guide 계열은 학습, Gambler 계열은 중간 검증, Duelist 계열은 최종 평가, Instructor/Sage는 예비로 배정했다. 각각의 모든 분기·기억 조건·말바꾸기는 같은 묶음에 남긴다. 검증/평가 계열의 Explanation에는 세부 의미가 비어 있는 부분이 있어 정답/평가 기준 완성으로 간주하지 않는다. 입력 경로를 확보한 것과 최종 평가가 가능한 것은 구분한다.

TrainingEnvironment.json과 AgentScripts/TrainingEnvironmentCheck.py에 읽기 전용 환경 점검을 기록했다. 설치 GGUF의 실제 SHA256과 크기는 기존 명세와 일치한다. 조사한 Python 3.12에는 torch/transformers/peft 등 학습 패키지가 없고, 표준 Hugging Face 캐시에서는 해당 학습용 모델을 발견하지 못했다. 다른 설치 경로의 존재까지 부정하지 않는다. GTX 1660 SUPER의 전체 VRAM은 6144 MiB이고 조회 시 여유는 약 4640 MiB였다. 실제 학습 메모리는 아직 측정하지 않았다.

[공식 GGUF 모델 카드](https://huggingface.co/google/gemma-3-4b-it-qat-q4_0-gguf)가 연결하는 반정밀도 모델 후보는 [google/gemma-3-4b-it](https://huggingface.co/google/gemma-3-4b-it)다. 이것이 현재 QAT GGUF와 동일한 학습 체크포인트라는 뜻은 아니다. 정확한 학습 revision을 고정하고, 학습하지 않은 원본의 변환 결과를 QAT 기준 모델과 먼저 비교해야 학습 효과와 원본/양자화 차이를 구분할 수 있다. 직접 LoRA 적용과 병합 후 변환 모두 현재 내장 런타임에서 미검증이다.

학습은 실행하지 않았다. 다음 준비는 검증/평가 장면의 근거 있는 평가 기준 확보, 정확한 학습 체크포인트와 격리 도구 환경 준비, 실제 입력 토큰 길이 확인, 1회 forward/backward 및 어댑터 저장/재로딩 메모리 시험이다. 6GB 가능 여부나 3분 생성 목표 달성을 추측으로 판정하지 않는다. 학습 방법은 이 시험 결과로 결정하며 [공식 학습 안내](https://ai.google.dev/gemma/docs/tune)의 소규모 자료·미학습 평가·배포 형식 확인 순서를 따른다.

## Colab 준비와 실행 착수

사용자는 무료 클라우드 학습 후 로컬 보완 방식을 요청했고, 구체적인 자료 6쌍과 코드의 Google Colab 업로드·실행도 승인했다. Tests/LocalStoryBenchmark/Colab에 자기 완결형 노트북·실험 설정·고정 패키지 후보·안내를 추가했다. AgentScripts/ColabTraining은 기존 자료로 bundle을 만들고, 승인·의미 정렬·묶음 누수·파일 무결성을 검사하며 assistant 응답에만 학습 손실을 적용한다. 사실·정답을 토큰 길이에 맞추어 자르지 않는다.

2026-10-29 Colab에 노트북을 업로드하고 T4 GPU 런타임 연결을 확인했다. 최초 설치 검사에서는 Colab 기본 Gradio/Diffusers와 고정 학습 패키지의 의존성 차이가 발견됐다. 전체 pip 검사 보고서는 보존하고, 실제 학습 스택의 고정 버전·직접 의존성과 실제 import를 검사하는 방식으로 수정했다. 실행 결과와 사용자 계정 단계는 Colab/README.md에 기록한다. GPU 할당이나 패키지 설치를 학습 완료로 보고하지 않는다.

로컬에서는 노트북 코드 셀 7개의 구문, 내장 bundle과 zip의 일치, 정상 자료 6쌍 및 다섯 가지 거부 조건을 검사했다. 미승인 자료·형식 검사 실패·최종 평가 묶음 누수·승인 이후 정답 변경·파일 변조를 모두 거부했다. 모델·DLL·토큰·개인 세이브는 bundle에 포함하지 않았다. 현재 게임 코드와 발표 설정은 유지한다.

## 미학습 장면 16회 탐색 비교 완료

Gambler 검증 계열과 Duelist 평가 계열의 기본 장면을 사용해 동일 HF 원본에서 LoRA 비활성/활성, 두 시드, 총 16회 생성했다. 안내와 선택 구간 모두 실제 게임 모듈에서 조립했다. 기존 학습 Guide 계열은 섞지 않았다. 사용자에게 새 두 장면의 Colab 전송·실행 승인을 받은 뒤 수행했다.

검토 권고는 이번 어댑터의 게임 채택 보류다. 형식 접두사의 일부 개선은 있었지만 다중 카드 누락, 입력 선택지 객체 복사, 원래 행동 의도 변경, 입력에 없는 도박 조건 추가가 남았다. 예를 들어 학습 후 대련 선택지의 '검을 살펴본다'는 원문의 '방어 자세를 살핀다'와 다르다. 실제 출력과 원문 근거를 ComparisonReviewed.html에 나란히 보이고 EvaluationReview.json에 검토 내용을 보관했다. 원시 출력과 미승인 검토 내용은 학습에 넣지 않았다.

이 비교는 게임 GBNF 없는 HF NF4 실행이고 세부 Explanation 의미가 비어 있는 항목에는 Story 원문을 보조 참조했다. 따라서 현재 QAT GGUF 대비 최종 효과 검증이나 게임 성능 판정은 아니다. 빈 의미 항목을 임의로 작성하지 않았다. 향후 이 대련 출력으로 자료를 보완한다면 해당 계열을 새로운 최종 평가용으로 재사용하지 않는다. 자료 수만 늘리기 전에 의미 자료의 완성도·다중 카드/선택 의도 대비 자료와 다른 모델의 동일 조건 비교를 검토한다. 이번 작업에서 발표용 기준은 바꾸지 않았다.
