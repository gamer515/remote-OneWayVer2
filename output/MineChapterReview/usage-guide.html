3-4. NPC 추가·교체

  1. 사용할 모델·리그·클립을 준비하고 AiAsset의 해당 팩에 둡니다.

3-5. 장소·청크 추가

  1. 실제 방·통로·문이 있는 맵 프리팹을 준비합니다. 배치할 건물은 하나의 그룹 아래에 개별 자식으로 두고, 각 건물의 기준점 Z를 해당 장소의 기준 위치와 맞춥니다.
  2. Terrain.json의 에피소드 TerrainInfo에서 chunkCount, chunkLength, groundIds, places를 맞춥니다. 장소마다 placeId, chunkIndex, prefabId, characterId, connectStoryCards를 지정합니다.

  4. DecisionScene → 환경 오브젝트의 EnvController → Ground Entries에서 해당 Ground ID의 Room Group에 건물 그룹 경로를 입력합니다. 분리된 지붕 그룹은 Room Companion Group에 입력합니다. 빈 청크에서 기존 테마의 건물을 재사용하려면 Room Source Ground Id에 원본 Ground ID를 입력합니다.

  6. 새 회차에서 징수원 경로, 청크 경계와 다음 에피소드 전환을 확인합니다. 간격은 Saves/ContentAuthoring/Places.xlsx의 facilitySpacing으로 조정합니다. 일반·특화 장소 합계의 상한은 4곳입니다.

갱도 징수원은 현재 이야기 장소 네 곳의 경로를 사용합니다. 에셋이 필요한 시설은 데이터상 위치와 용도를 먼저 확인하고, 해당 챕터의 프리팹과 상호작용을 연결합니다.

  5. 현재 보스 준비 청크에서 메뉴로 돌아가는 전용 조건을 수정해야 다음 챕터로 이어집니다. 새 챕터에 노동·징수·첫 만남을 쓰려면 청크 1 전용 설정·실행 범위도 일반화해야 합니다.

  5. Play를 종료한 뒤 메인 메뉴부터 다시 실행합니다. 카탈로그 캐시, 저장된 대화 스냅샷, 이미 해결한 장소 때문에 진행 중 화면만으로 원본 반영 여부를 판단하면 안 됩니다.
  6. 새 분기, 정상 지불·부족, 승패, 재시작 저장 복원, 다음 장소·청크·챕터까지 해당 범위를 확인합니다. 테스트 저장을 구분하고 사용자 기존 저장을 임의로 삭제하지 마세요.

자동 검사 도우미는 AgentScripts/MineChapterChecks.cs와 MineChapterRevisionChecks.cs입니다. Unity 연동 도구로 실행하는 개발용 파일이며 일반 사용자용 버튼은 아닙니다. 현재 102개 이야기·4개 장소·8개 배우 같은 검사 기대값이 있어 콘텐츠 수를 늘리면 검사도 함께 갱신해야 합니다.

기획 텍스트·생성 스크립트

Desktop의 이야기.txt·게임진행.txt는 기획 원본입니다. 텍스트만 수정하면 JSON이 자동 갱신되지는 않습니다. AgentScripts/BuildMineChapter.py는 현재 원문의 줄 범위·8명 이름을 기준으로 가져오므로, 글을 임의로 늘린 뒤 그대로 실행하는 범용 가져오기 도구가 아닙니다. 여러 JSON을 다시 쓰므로 직접 수정한 데이터를 덮어쓰지 않도록 원문·JSON 관리 방식을 정하고 변경 차이를 확인하세요.

PrepareMineChapter.cs도 맵·참조 준비용 개발 도구입니다. 이름 목록에 NPC를 추가하면 모든 콘텐츠를 만드는 프로그램이 아닙니다. 필요한 변경만 적용해야 합니다.

7. 에셋 제공

NPC 8명 외형과 Boss1 대기·포효 클립은 이미 있습니다. 후속 연출에는 일반 NPC·징수원의 리그/대기/걷기/대화, 노동·강제 휴식·경주·NPC별 결투 클립 연결이 필요합니다. 새 콘텐츠는 사용할 모델·리그·클립·장소를 함께 지정하세요. 현재 미작업 항목은 최신 O/X 작업표에서 확인할 수 있습니다.
