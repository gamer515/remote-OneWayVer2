미리보기 씬을 열고 Play하면 전용 Animator Controller가 한 번 재생하고 끝 자세를 유지한다. FrontCamera가 기본 활성 카메라다. 옆에서 보려면 FrontCamera를 끄고 SideCamera를 켠다. 게임 씬에 사용할 때는 연결이 완료된 리그 프리팹을 배치한다.

그릇은 독립 프리팹의 중첩 인스턴스다. 미리보기 리그의 Bowl에만 Parent Constraint가 추가되어 Hand/CoinBowlGrip을 따라간다. 클립이 32프레임에서 Constraint weight를 0에서 1로 전환한다. 연결 오프셋을 잡는 자세에서 계산해 전환 때 위치·회전이 이어진다. 32프레임 이전에는 그릇이 바닥 위치에 고정된다. 코인은 kinematic으로 두고 그릇 안 로컬 위치를 유지한다.

클립의 경로는 Hand 아래 기존 변형 본 계층을 사용한다. 전체 리그 루트에서 재생하면 손 동작과 Bowl의 연결이 함께 동작한다. 손만 원래 Animator에 적용할 때는 Hand 경로와 Bowl의 Parent Constraint 연결이 같은 구조인지 맞춰야 한다. 이번 작업에서 원래 게임 Animator나 이벤트에 자동 연결하지 않았다.

기존 리그 조사와 제작 방식

원본 Assets/Decision_YYS/Prafabs/Hand.prefab 및 HandRoot를 확인했다. hand_game-rig/DEF-upper_arm.L 아래 DEF-hand.L, index·middle·pinky의 세 손가락과 thumb의 3관절 체인이 있다. 손 스킨은 20개 변형 본을 사용한다. 기존 HandAnimController에는 Duel_Idle, PlayerGuardSlot, PlayerParrySlot, Slach_Attack이 연결되어 있었다.

프로젝트의 Blender 파일과 AssetBuild를 검색했으며 손과 호환되는 .blend 원본은 찾지 못했다. Assets/UnityAssets/three-finger-hand_Paid_Unity.fbx와 AssetBuild/ThreeFingerHandPaid/three-finger-hand_Paid.fbx를 확인했다. Unity 프리팹 복제본에서 FBX의 열린 자세를 기준으로 변형 본 회전을 직접 베이크했다. 기존 프리팹의 검은 작업 복제본에서 제거했다. 기본 그릇 지름에 맞춰 미리보기 손의 루트 Scale은 0.065로 설정했다.

검증 결과와 범위

기존 게임과 분리한 작은 Unity 프로젝트를 생성해 정상 Animator 자동 재생을 확인했다. 이후 0~72프레임을 한 프레임씩 샘플링해 실제 Unity Parent Constraint 결과를 읽었다. 31프레임까지 그릇 위치 변화는 0이며 32프레임의 연결 오차는 약 7.45×10⁻⁹m였다. 들어 올리는 동안 상대 위치 오차도 같은 수준이며 그릇의 기울기는 0°였다. 1초 끝 위치와 이후 유지 자세를 확인했고 코인 로컬 위치 변화는 0이었다.

실제 SkinnedMeshRenderer를 베이크한 손 메시의 모든 정점을 그릇 벽 Collider에 대해 0~60프레임에서 검사했다. 0.25mm 내부 허용 오차를 두었을 때 벽 내부로 들어간 정점은 모든 샘플에서 0개였다. 앞·옆 렌더도 직접 확인했다. 이 검사는 프레임 샘플과 정점·기존 Collider 기준이며 연속 표면의 수학적 무교차 증명은 아니다.

원 프로젝트의 검토 이미지는 기존 URP 재질로 렌더링했다. 별도 프로젝트의 Play 캡처는 재질 색상과 텍스처를 복제한 Built-in Standard 렌더러를 사용했다. 이 렌더러 변환은 검증 복제 프로젝트 안에서만 수행했다. 새 미리보기 씬은 원래 Unity 프로젝트의 URP 재질을 사용한다.

재현·수정 도구

PickupAuthoring.cs의 Build가 전용 에셋을 제작한다. 클립 길이·접촉 시점과 손가락 각도는 이 도구의 상수와 Pose 함수에서 수정한다. PrepareIsolatedProject는 최종 에셋과 PickupPlayCheck.cs를 검증 프로젝트로 복제한다. 해당 프로젝트를 batchmode로 열어 PickupPlayCheck.Start를 실행하면 정상 재생·프레임 검사와 캡처를 수행한 뒤 종료한다. BuildPreviewAnimation.cjs는 캡처를 앞·옆 APNG로 묶는다.

참고한 작업 지침은 using-unity, unity-cli.md, unity-pipeline.md, Pipeline Documentation~/commands/scripts.md 및 development-principles였다.

작업 분리와 정리

기존 손 프리팹·FBX·HandAnimController·기존 클립·WoodenCoinBowl 원본은 수정하지 않았다. 게임 씬을 저장하거나 원래 에디터를 Play로 전환하지 않았다. 새 애니메이션과 프리팹·미리보기 씬은 Assets/ThreeFingersCoinBowlPickup 아래에, 유지할 도구는 AssetBuild/ThreeFingersCoinBowlPickup 아래에만 작성했다.

검증용 AssetBuild/ThreeFingersCoinBowlPickup/ValidationProject와 초기 조사 로그·프로세스 기록은 정리했다. 검증 복제 프로젝트의 357개 파일, 약 12.7MiB를 제거했다. 삭제 전에 작업 폴더 경계·심볼릭 링크·검증 프로세스 종료를 확인했다. 삭제 대기 임시 코드는 없다. 재현 도구 3개와 최종 검증 JSON·이미지·클립·미리보기 씬은 보존했다. 커밋·푸시는 수행하지 않았다.
